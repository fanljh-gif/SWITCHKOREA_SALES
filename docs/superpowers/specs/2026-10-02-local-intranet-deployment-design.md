# SWITCH KOREA 영업관리 시스템 로컬 사내망 배포 설계

## 1. 목적

현재 사용 중인 Windows PC `JHLEE`를 SWITCH KOREA 영업관리 시스템의 1차 사내 서버로 사용한다. 팀장과 네 명의 팀원이 각자 PC의 브라우저에서 HTTPS로 로그인하고, 권한 범위 안에서 거래처·단가·출고 및 관리 데이터를 직접 등록하도록 한다. 데이터는 PostgreSQL에 영구 저장하며 Windows 재부팅 후에도 서비스와 백업이 자동으로 동작해야 한다.

## 2. 확정 범위

- 서버 PC: `JHLEE`
- 접속 주소: `https://sales.switchkorea.local`
- 접속 범위: 사내망 내 담당자 PC
- 웹 호스팅: IIS + ASP.NET Core Hosting Bundle
- 데이터베이스: 서버 PC의 PostgreSQL Windows 서비스
- 백업 위치: `C:\SwitchKorea\Backups`
- 백업 일정: 매일 오전 2시
- 백업 보관기간: 30일
- 설치 위치: `C:\SwitchKorea\SalesManagement`
- 인증서 공개 배포 위치: `C:\SwitchKorea\Certificates\SwitchKorea-RootCA.cer`
- 초기 자격증명 위치: `C:\SwitchKorea\Secrets\initial-credentials.txt`

PostgreSQL은 외부 네트워크에 공개하지 않고 서버 PC의 API에서만 접속한다. 사내 사용자는 HTTPS 443 포트의 웹 시스템만 이용한다.

## 3. 구성도와 데이터 흐름

```text
담당자 PC 브라우저
  └─ HTTPS 443 / sales.switchkorea.local
       └─ Windows 방화벽: 사내망 CIDR만 허용
            └─ IIS
                 ├─ React 정적 화면
                 └─ /api → ASP.NET Core API
                              └─ localhost PostgreSQL

Windows 작업 스케줄러
  └─ 매일 02:00 pg_dump
       └─ C:\SwitchKorea\Backups (30일 보관)
```

React와 API를 동일 IIS 사이트에서 제공해 쿠키 인증의 동일 출처 정책을 유지한다. 연결 문자열은 저장소나 일반 설정 파일에 기록하지 않고 보호된 Machine 범위 설정으로 주입한다.

## 4. 초기 계정

| 역할 | 성명 | 로그인 ID | 이메일 |
|---|---|---|---|
| 팀장 | 이재학 | `jhlee` | `jhlee@switchkorea.com` |
| 팀원 | 박태원 | `twpark` | `ptw0517@switchkorea.com` |
| 팀원 | 최명철 | `mcchoi` | `cmc@switchkorea.com` |
| 팀원 | 이소연 | `sylee` | `sylee@switchkorea.com` |
| 팀원 | 이창선 | `cslee` | `cslee@switchkorea.com` |

계정별로 암호학적으로 안전한 서로 다른 임시 비밀번호를 생성한다. 비밀번호 원문은 데이터베이스·애플리케이션 로그·Git에 저장하지 않는다. 배포 과정에서 생성되는 초기 자격증명 파일은 현재 Windows 사용자와 로컬 Administrators만 읽도록 ACL을 제한하고, 모든 사용자의 최초 변경 완료 후 삭제한다. 초기화 작업은 재실행해도 기존 계정과 비밀번호를 덮어쓰지 않는다.

## 5. 권한

- 팀원은 자기 담당 거래처와 그 거래처의 단가·출고를 등록하고 수정할 수 있다.
- 팀원은 다른 담당자의 거래처와 연결된 데이터를 수정할 수 없다.
- 팀장은 전체 거래처, 품목, 환율, 목표, 사용자, 담당자 변경을 관리한다.
- 최초 로그인 사용자는 업무 화면 진입 전에 비밀번호를 변경해야 한다.
- 로그인 실패 잠금, 비활성 계정 차단, 세션 만료 및 감사 이력 규칙은 기존 시스템 정책을 유지한다.

## 6. HTTPS와 이름 해석

서버 PC에서 SWITCH KOREA 전용 자체 루트 인증기관과 `sales.switchkorea.local` 서버 인증서를 생성한다. 루트 인증서의 개인키와 서버 인증서 개인키는 서버의 LocalMachine 인증서 저장소에 보관하고 외부로 배포하지 않는다. 담당자 PC에는 공개 루트 인증서 `.cer`만 신뢰할 수 있는 루트 인증기관 저장소에 설치한다.

정식 사내 DNS에 `sales.switchkorea.local`이 `JHLEE`의 고정 IPv4 주소를 가리키도록 등록한다. DNS 등록 전 검증 단계에서는 동일 매핑을 각 담당자 PC의 hosts 파일에 임시 적용한다. 서버 IP는 설치 시 실제 네트워크 값을 확인하여 명시적으로 입력하고, 동적 주소라면 DHCP 예약 또는 고정 주소를 먼저 설정한다.

## 7. 설치 절차

설치 자동화는 관리자 권한으로 다음 순서를 수행한다.

1. Windows 버전, 관리자 권한, 고정 IPv4, 디스크 여유 공간을 사전 점검한다.
2. IIS, ASP.NET Core Hosting Bundle, PostgreSQL 및 client 도구 설치 상태를 확인하고 필요한 구성 요소를 설치한다.
3. PostgreSQL 서비스를 localhost 전용으로 구성하고 `switch_korea_sales` 데이터베이스와 최소 권한 애플리케이션 계정을 생성한다.
4. 초기 migration을 적용하고 스키마 제약조건을 확인한다.
5. 팀장과 팀원 초기 계정을 멱등 방식으로 생성한다.
6. Front-end와 API 통합 게시물을 `C:\SwitchKorea\SalesManagement`에 배포한다.
7. 루트·서버 인증서 생성, IIS HTTPS 바인딩, 앱 풀 자동 시작을 구성한다.
8. Windows 방화벽에 사내망 CIDR 대상 HTTPS 443 규칙을 추가한다.
9. 매일 오전 2시 백업 작업과 30일 정리 정책을 등록한다.
10. 설치 결과, 인증서 배포 파일, 초기 자격증명 파일 및 담당자 PC 설정 절차를 출력한다.

구성 요소 설치처럼 재부팅이 필요한 단계에서는 상태 파일을 남겨 재부팅 후 같은 설치 명령으로 안전하게 이어갈 수 있게 한다. 각 단계는 이미 완료되었는지 확인한 후 실행한다.

## 8. 백업과 복원

백업은 PostgreSQL custom format을 사용하며 `switch_korea_sales-YYYYMMDD-HHmmss.dump` 형식으로 저장한다. 성공한 파일만 보관 대상으로 인정하고, 30일보다 오래된 동일 DB 백업을 삭제한다. 실패 시 0이 아닌 종료코드와 Windows 이벤트 로그를 남긴다.

복원은 운영 DB를 기본 대상으로 삼지 않는다. 먼저 별도 검증 DB에 `--single-transaction`으로 복원하고 사용자·거래처·출고·감사 이력 건수를 비교한다. 운영 DB 복원은 명시적인 대상 DB, 백업 파일, 서비스 중지 및 고위험 확인 절차 없이는 실행하지 않는다.

로컬 디스크 백업은 서버 PC 자체 고장에 취약하므로 1차 운영 이후 NAS나 별도 저장장치로 복사하는 2차 백업을 후속 운영 과제로 남긴다.

## 9. 오류 처리와 보안

- 설치 로그는 단계명·시간·종료코드만 기록하며 비밀번호와 연결 문자열을 마스킹한다.
- PostgreSQL 포트는 외부 방화벽 규칙을 만들지 않는다.
- IIS는 HTTPS만 업무용으로 공개하고 HTTP 요청은 HTTPS로 전환한다.
- 인증서 생성·설치 실패, migration 실패, 초기 계정 실패, 백업 검증 실패는 설치 성공으로 처리하지 않는다.
- 초기 자격증명 파일과 DB 연결 정보는 최소 ACL을 적용한다.
- 서버 PC 절전으로 서비스가 중단되지 않도록 전원 정책을 운영 전 확인한다.

## 10. 검증 기준

다음 항목이 모두 충족되어야 실사용 가능 상태로 판정한다.

1. 서버 재부팅 후 IIS와 PostgreSQL이 자동 시작한다.
2. 서버와 담당자 PC에서 `https://sales.switchkorea.local` 접속 시 인증서 경고가 없다.
3. 다섯 계정이 각각 로그인하고 최초 비밀번호를 변경할 수 있다.
4. 팀원이 자기 거래처·단가·출고를 등록하고 다른 담당자의 자료 수정은 거부된다.
5. 팀장이 품목·환율·목표·사용자를 관리할 수 있다.
6. 등록 데이터가 재접속과 서버 재시작 후 유지된다.
7. 매일 백업 작업을 수동 실행해 백업 파일과 성공 종료코드를 확인한다.
8. 별도 검증 DB 복원 후 핵심 테이블 건수가 원본과 일치한다.
9. 사내망 허용 범위 밖에서는 443 포트에 접근할 수 없다.
10. 애플리케이션·설치·백업 로그에 평문 비밀번호와 연결 문자열이 없다.

## 11. 구현 범위와 비범위

이번 작업에는 설치 자동화, 초기 계정 부트스트랩, HTTPS 인증서 생성·배포 파일, 로컬 PostgreSQL, IIS, 방화벽, 작업 스케줄러, 백업·검증 복원이 포함된다.

사내 DNS 서버의 실제 레코드 등록, 각 담당자 PC의 관리자 권한 작업, 외부 인터넷 공개, 모바일 외부 접속, 고가용성, 원격지 재해복구 및 NAS 2차 백업은 포함하지 않는다. 대신 DNS/hosts와 인증서 배포에 필요한 정확한 명령과 파일을 제공한다.
